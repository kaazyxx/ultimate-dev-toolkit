# Design Patterns

**Category:** architecture

## Checklist

- Pattern reduces complexity, not adds it
- Named after intent, not mechanism
- Language idioms preferred over forced patterns

## Common pitfalls

- Pattern soup / over-abstraction
- Singletons as global mutable state
- Forcing GoF patterns onto simple problems
